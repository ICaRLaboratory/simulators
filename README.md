# Control Simulators

설치와 로그인 없이 브라우저에서 제어를 체험하는 교육용 시뮬레이터 모음입니다.

게시 주소: https://icarlaboratory.github.io/simulators/

## 범위

- 참고 강의자료의 프로젝트를 찾아보는 검색·분류 대시보드
- 개별 실험 21개: 장치 실험 16개와 그래프 전용 실험 5개(PID, MPC, DeePC, SMC, TDC)
- 기존 Research의 로봇 궤적 추종·접촉 제어로 바로 연결
- 한국어/EN 전환; 언어를 바꿔도 실험 상태 유지
- 전체 23개 카드 실행 가능: 로컬 실험 21개 + Research 연결 2개
- 로그인, 다운로드, 과제 제출, 결과 저장 및 분석 추적 기능 없음
- 기존 연구실 사이트는 수정하지 않습니다.

## 모델과 출처

이 저장소의 실험은 원본 MATLAB/Simulink 파일을 변환하거나 실행하는 것이 아닙니다. 해당 교육 주제에서 핵심 원리를 경험하도록 독립 구현한 단순화 모델입니다. 원본과 결과가 동일하다고 보장하지 않으며, 실제 장비 설계나 안전성 판단에 사용하지 마세요.

카드와 실험 페이지의 출처 링크는 해당 제어 원리를 다룬 논문, MathWorks 자료 또는 CTMS 튜토리얼로 연결합니다. 논문 링크는 개념 참고 문헌이며 코드 라이선스를 뜻하지 않습니다. 각 실험 페이지에는 모델의 한계를 설명합니다. 입력 제한·미분 구현·마찰 등은 학습용 선택이며 원본 장치의 식별된 파라미터가 아닙니다.

[실험별 출처와 재사용 조건](docs/simulator-sources.md)에서 수치 모델의 대응 관계, 주제만 참고한 자료, 실제로 포함된 형상을 구분합니다.

- 크루즈 컨트롤: 질량·선형 저항·부하를 갖는 종방향 속도 모델
- DC 모터: 전기 회로를 생략한 2차 위치 응답 모델
- 볼 앤 빔: 이상화한 공의 구름 운동, 이상적인 빔 각도 구동. 빔 끝을 넘으면 중단
- 도립진자: 카트와 질점 진자의 비선형 운동, 전체 상태 피드백과 ±20 N 힘 제한. 카트 레일 ±2 m 또는 진자 기울기 ±60°에 도달하면 중단

- 회전 도립진자: 회전 암·진자의 결합 비선형 질량행렬, 직립 전상태 피드백
- 볼 앤 플레이트: 두 축 구름 운동, 축별 PD, 기울기 제한·판 이탈 정지
- 로봇 암: 2관절 관성·코리올리·중력 결합, 관절별 PID·중력 보상
- 자동 주차: 전진 정렬·후진 경로 추종, 자전거 운동학, 목표 자세·차체 경계 검사
- 열교환기: 혼합 용적의 유입·유출·열전달 에너지 수지와 온도 PI
- 드론: 평면 쿼드콥터, 로터 쌍 추력 배분·고도 PID·롤 PD
- 임피던스 로봇: Kinova Gen3의 2·4·6번 관절만 움직이는 시상면 모델. 끝점이 수직 벽을 누를 때 강성과 감쇠에 따른 접촉력·변위를 비교
- 차량 경로 추종: 자전거 운동학과 Pure pursuit, 원형 경로·횡오차
- 능동 서스펜션: 차체·휠 2질량 쿼터카, 노면 요철·스카이훅 피드백
- CSTR: 농도·온도 비선형 수지, Arrhenius 반응·냉각 재킷 PI
- 항공기 피치: 받음각·피치율·피치각 상태 공간, 승강타 PID·입력 제한
- 로켓 수직 착륙: 평면 강체·두 엔진 추력 배분, 위치·하강·자세 피드백, 연착륙 판정. [조사 자료와 모델 범위](docs/rocket-landing-sources.md)
- [2차 LTI 시스템의 PID 제어](pid-lti/): 단위 계단응답과 P·I·D 항별 제어입력을 비교합니다. 현재 응답을 고정한 뒤 제어기 또는 플랜트 설정을 바꾸면 같은 초기조건에서 응답을 다시 계산합니다. D항은 측정 출력에 적용하며, 정상상태 오차는 안정한 폐루프에 대해서만 표시합니다. [관련 자료: CTMS의 PID 제어기 설계](https://ctms.engin.umich.edu/CTMS/?example=Introduction&section=ControlPID)
- [2차 LTI 시스템의 MPC 제어](mpc-lti/): 예측 구간, 입력 변화 가중치, 입력 한계를 바꾸며 MPC의 단위 계단응답을 살펴봅니다. 계획 시점을 선택하면 그때의 예측 출력·입력과 실제 폐루프 궤적을 확인할 수 있습니다. [관련 자료: MathWorks의 What Is Model Predictive Control?](https://www.mathworks.com/help/mpc/gs/what-is-mpc.html)
- [데이터 기반 예측 제어(DeePC)](deepc-lti/): 결정론적 2차 시스템에서 잡음 없이 측정한 입출력 데이터로 미래 출력을 예측합니다. 기록할 때 입력을 일정하게 유지하면 어떤 정보가 부족해지는지 확인합니다. [Coulson, Lygeros & Dörfler, *Data-Enabled Predictive Control: In the Shallows of the DeePC* (2019)](https://doi.org/10.23919/ECC.2019.8795639)
- [슬라이딩 모드 제어(SMC)](smc-lti/): 오차와 오차 변화율의 위상 평면에서 궤적과 슬라이딩 면을 관찰하고 경계층 폭에 따른 스위칭 입력의 변화를 확인합니다. [Utkin, *Variable Structure Systems with Sliding Modes* (1977)](https://doi.org/10.1109/TAC.1977.1101446)
- [시간 지연 제어(TDC)](tdc-lti/): 과거의 가속도와 같은 시점의 제어입력으로 미지의 동역학을 추정합니다. 지연을 바꿔 외란이 가해진 뒤의 추정값과 실제값을 비교합니다. [Youcef-Toumi & Ito, *A Time Delay Controller for Systems With Unknown Dynamics* (1990)](https://doi.org/10.1115/1.2894130)

다섯 LTI 실험은 `G(s) = Kωₙ²/(s² + 2ζωₙs + ωₙ²)`를 공유합니다. 고유진동수(0.5–2 rad/s), 감쇠비(0.1–2), 정상상태 이득(0.5–2)을 바꿀 수 있습니다. 기본값은 각각 1, 0.5, 1입니다. 실험 간 이동 링크와 현재 URL에는 기본값과 다른 플랜트 설정이 반영됩니다.

각 모델의 단위·가정·제어식·정지 조건은 해당 페이지의 접힌 모델 설명에 제공합니다.

## 로컬 실행

Node.js 22 이상과 Python 3 권장. 웹사이트 자체에는 빌드나 npm 의존성이 필요하지 않습니다.

```sh
python3 -m http.server 8765 --directory ..
# 상위 폴더 아래 simulators라는 폴더에 체크아웃한 경우:
# http://localhost:8765/simulators/
```

ES modules를 사용하므로 파일 더블클릭 대신 HTTP 서버로 여세요.

## 장치 시각화

16개 장치 화면은 자체 호스팅한 Three.js 0.187.0으로 표시합니다. 기본 동역학·제어식·수치 적분 방법과 응답 그래프의 구조를 유지하며, 실험 배치를 바꿀 때는 모델 좌표와 표시를 함께 맞춥니다. 입체 표현이 평면 모델의 물리적 자유도를 추가하지는 않습니다.

- `assets/three/`: 장치별 읽기 전용 장면과 공통 카메라·렌더러. 드래그 회전, 스크롤 확대·축소, 방향키 회전, `+`/`-` 확대·축소, `Home` 및 시점 초기화 버튼을 지원합니다.
- 카메라 조작은 시뮬레이션을 진행하거나 초기화하지 않습니다. 자동 카메라 회전은 없습니다.
- 로봇 암 다중 루프 제어(EXP 07)는 좁은 화면에서 별도의 가로 작업영역 경계를 사용합니다. 고정된 시점에서 연속 작업영역과 과도응답이 잘리지 않는지 검사합니다.
- 임피던스 제어(EXP 11)는 [MathWorks 예제](https://github.com/mathworks/Robotic-Arm-Impedance-Control)의 Gen3 홈 자세에서 시작합니다. 3D 형상은 7관절 로봇을 나타내지만 1·3·5·7번 관절은 고정됩니다. 빨간 구는 실제 끝점이 아니라 기준 위치입니다. 기본 설정에서 이 구는 벽 앞 10 cm에서 출발해 0.5~2초 동안 벽 안쪽 5 cm까지 이동합니다. 실제 끝점의 침투 깊이와 접촉력은 벽과 로봇의 응답으로 결정되며 목표 힘을 지정하지 않습니다.
- `engineering.js`는 가공 금속·도장·고무 등 부품 재질과 형상을, `lighting.js`는 외부 이미지 없이 생성하는 조명 환경을 담당합니다. `camera.js`의 원근 투영을 실제 장면과 기하 검사에서 함께 사용합니다.
- `robot-hardware.js`는 닫힌 곡면 링크 외장을 생성합니다. 관절 반경을 왜곡하지 않고 링크 길이를 반영하며, 기존 기하 버퍼를 재사용합니다. 외장 형상은 모델의 질량·관성·자유도를 추가하지 않습니다. `tests/robot-hardware.test.js`에서 표면 방향·입체 형상·입력 검증·버퍼 재사용을 검사합니다.
- 장치 옆 계측 표시는 실제 상태·파라미터를 읽는 `readouts()`에서 가져옵니다. 부품에 연결된 설명선은 카메라를 따라 갱신되며, 작은 화면에서는 일부 보조 표시를 줄이되 기존 수치와 그래프는 유지합니다. 모델에 없는 회전수·유량을 계산된 계측값처럼 표시하지 않습니다.
- 드론의 프로펠러 회전·잔상은 기존 시뮬레이션 시간에 따른 시각 효과이며 실제 RPM 계산이 아닙니다. 일시정지·초기화 및 본체/확대도의 동작을 일치시키고, 모터 동역학이나 별도의 애니메이션 시계를 추가하지 않습니다. 추력 표시와 비행·롤 계산은 기존 모델을 그대로 사용합니다.
- 열교환기와 CSTR의 유체·재킷 색은 계산된 온도를 나타내는 상태 색상입니다. 두 장치 모두 섭씨 기준을 사용하되 CSTR의 내부 Kelvin 값을 변환합니다. 색상은 금속의 발광이나 별도로 계산한 벽 온도가 아니며, 균일 혼합 온도를 공간 온도 분포처럼 표현하지 않습니다. 열입력·열교환 및 유동 표시는 실제 상태·설정에 연결하고, 별도 시계·기포·상변화·액면 변화는 추가하지 않습니다. CSTR의 체적은 100 L로 일정하며 농도는 온도와 구분해 표시합니다.
- WebGL2가 없거나 그래픽 컨텍스트를 잃으면 기존 Canvas 2D 장치 화면을 사용합니다.
- `assets/vendor/three.js`는 정확한 버전을 고정한 로컬 파일입니다. 방문자가 npm이나 CDN에 연결할 필요가 없습니다. 라이선스와 재생성 절차는 `assets/vendor/README.md`를 참고합니다.
- `tests/three-*.test.js`는 실제 상태와 장면 좌표·비변경성을, `tests/three-view.spec.js` 및 `tests/three-integration.spec.js`는 실제 WebGL·카메라·폴백·반응형을 검사합니다.

공통 형식의 12개 실험의 모델·번역·제어 구조 정의는 `assets/models/`에 있습니다. 정의 변경 후 `node scripts/build-experiment-pages.mjs`로 정적 페이지를 다시 생성합니다. 나머지 장치 실험 4개와 그래프 전용 실험 5개는 이 생성기를 사용하지 않습니다. DeePC·SMC·TDC 페이지는 `node scripts/build-method-labs.mjs`로 생성하고, `--check`로 현재 페이지가 생성 결과와 일치하는지 검사합니다.

## 재생 방식

16개 장치 실험은 정지 상태로 열립니다. ‘시작’을 누르거나 일시정지 후 다시 시작하면 기기의 `prefers-reduced-motion` 설정과 관계없이 브라우저의 매 화면 갱신 콜백에서 장치를 그립니다. 별도의 재생 옵션은 없습니다. 다른 장식 효과에는 기존의 동작 줄이기 설정을 유지합니다. 물리 계산은 고정 간격과 제한된 따라잡기 계산을 그대로 사용하므로 실험 속도는 바뀌지 않습니다. 숨겨진 탭은 일시정지하며, 탭으로 돌아오거나 초기화해도 자동으로 시작하지 않습니다. 그래프 전용 실험에는 장치 화면이나 재생 버튼이 없으며, 설정을 바꾸면 SVG 그래프와 응답 지표가 즉시 갱신됩니다.

개발 환경의 갱신 빈도는 `OUT=/tmp/playback-start.json node scripts/profile-playback.mjs`로 측정합니다. 시작 버튼만 눌러 두 OS 동작 설정에서 그리기 호출 빈도와 RAF 콜백 비용을 비교하며, `CPU_RATE=4`로 CPU 제한을 추가할 수 있습니다. 결과는 헤드리스 브라우저의 그리기 호출 빈도이며 사용자 기기의 실제 화면 FPS를 보장하지 않습니다.

## 대시보드 미리보기

카드에는 실제 실험 화면을 사용합니다. 로컬 서버를 실행한 뒤 `node scripts/capture-previews.mjs`로 23개 실험의 한국어·영어 미리보기 46개를 갱신합니다. 일부만 갱신하려면 ID를 공백으로 구분해 지정합니다. 예를 들어 다음 명령은 세 실험의 이미지 여섯 장만 캡처하고 나머지 이미지와 기록은 유지합니다.

```sh
node scripts/capture-previews.mjs deepc-lti smc-lti tdc-lti
```

새 실험을 여러 개 등록할 때는 누락된 ID를 한 명령에 모두 포함하세요. 기존 기록과 합쳐 모든 실험에 두 언어의 기록이 하나씩 있고 같은 언어의 이미지 해시가 중복되지 않는지 확인한 뒤에만 파일을 씁니다.

장치 실험 16개는 고정 시간 간격으로 실행한 장면을, Research 연결 2개는 해당 페이지의 장치 영역을 캡처합니다. PID 응답 분석 실험은 P 응답을 고정한 뒤 I항을 켜서 P와 PI 곡선이 함께 보이는 실제 응답 패널을 캡처합니다. MPC 실험은 초기 설정의 MPC 출력과 첫 계획의 예측 출력이 표시된 패널을 캡처합니다. DeePC·SMC·TDC는 다른 제어기의 곡선을 겹치지 않고, 기본 출력 곡선이 그려진 첫 응답 패널(`#method-response-panel`)을 캡처합니다. `assets/previews/manifest.json`에는 출처, 렌더러(`three` 또는 `svg`), 이미지 해시가 기록됩니다.

## 검증

```sh
npm ci --include=dev
npm test
npx playwright install chromium
npx playwright test tests/*.spec.js --workers=1
```

브라우저 검증은 기본적으로 위 로컬 서버를 사용합니다. 게시된 사이트 검증:

```sh
SIM_BASE=https://icarlaboratory.github.io/simulators/ npx playwright test tests/*.spec.js --workers=1
```

도립진자의 독립 수치 검증은 NumPy/SciPy가 설치된 Python 환경에서 `python3 scripts/verify-pendulum.py`로 실행합니다. 세 목표 위치와 각속도 외란을 포함한 응답을 질량행렬 기반 DOP853 해와 비교합니다.

로켓 모델은 `python3 scripts/verify-rocket.py`로 별도 구현한 SciPy DOP853 방정식과 비교합니다. 일정 추력·무추력·호버링 및 외란이 포함된 폐루프 응답을 검증합니다.

모델 단위 검증과 브라우저 조작 검증은 별도입니다. 브라우저에서 물체가 움직인다는 것만으로 모델의 정확성을 판정하지 않습니다.
